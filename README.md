# Riverbraid Evaluation Kit

> Lifecycle: ACTIVE_ARCHITECTURAL_SURFACE  
> Role: MECHANICAL_REPRODUCTION_PROFILE_OWNER  
> Protocol authority: NONE  
> Project authority: NONE

Riverbraid-Evaluation-Kit owns the **currently declared Riverbraid mechanical reproduction profile**. It evaluates bounded mechanical conditions; it does not certify Riverbraid or systems that use it.

Riverbraid does not decide truth, trust, evidentiary weight, legitimacy, risk, readiness, certification, moral priority, or the correct interpretation of evidence.

## Profile model

The historical 30-repository evaluation registry is preserved under a distinct historical profile identity. Its prior results remain historical evidence and are not rewritten into evidence for the lean topology.

The successor mechanical reproduction profile has exactly two technical roles:

1. this repository provides the evaluator/profile implementation; and
2. `Riverbraid-Core` is the mechanical subject.

Documentation, Governance, and `.github` are active architectural surfaces with routing/currentness/project-decision roles; they are not invented runtime verification targets. The five experimental survivors and all 42 historical repositories are excluded from this profile unless a later, separately identified profile explicitly includes them.

## What a scoped PASS means

A PASS means only that the named evaluator executed the named checks against the named subject under the recorded environment and the checks satisfied that profile's declared conditions.

Every result must carry its subject, profile/check contract, evaluator, environment, evidence references, and explicit nonclaims. A generic `PASS` or `external_reproduction: true` is insufficient.

An `INVALID_ATTEMPT` does not identify an accepted subject commit: `subject_commit` is `null`, while `attempted_subject_commit` preserves the supplied value for inspection. Non-`INVALID_ATTEMPT` results require an exact lowercase 40-hex `subject_commit` and omit `attempted_subject_commit`.

## Historical compatibility

The old 30-repository registry, expected-result surface, and workflow are retained as historical profile material with exact identity. New results must not be replayed across the historical and successor profile identities.
